# CopilotKit v2 integration

The experimental page `/app/agent-copilot` uses `CopilotKitProvider` and headless `useAgent` from the **v2** package entry point. It retains the Aster layout, locale, and existing `ActionVerification` component. The page is only mounted when `AGENT_UI_V2_ENABLED=true`; `/app/agent` is unchanged.

The browser first requests `/api/copilotkit/thread`. The server checks `/customer/session` and derives an opaque thread ID from the HttpOnly Spring session cookie. The browser never receives the cookie value. The route `/api/copilotkit/[...path]` checks origin and bank session on each request, accepts only `info`, `agent/aster/run`, `connect`, session-owned `stop`, and that session's read-only `threads/{id}/messages`, and forwards to the Python AG-UI endpoint through a **new `HttpAgent` for each request**. It blocks CopilotKit's default thread-list, memory, inspector, and other routes. A separate `/api/copilotkit/thread-state` request derives the same owned ID server-side and asks the Agent for the current task status, so a pending bank review can reappear after a page refresh. The server never accepts a client-selected bank tool or customer identity. Set `ASTER_BANKING_CORE_URL` and `ASTER_AGENT_RUNTIME_URL` to fixed server-side origins; the Compose overlay configures these and disables CopilotKit telemetry. The browser does not call the internal Agent or Spring execution endpoints directly.

The page shows assistant messages and actual tool lifecycle events. When the Agent reports `WAITING_CONFIRMATION`, it retrieves the current task through the existing authenticated task endpoint and renders only parsed, selected bank-owned review terms. Confirmation calls the existing `/api/agent/chat` trusted action route, including step-up authorization where required; cancellation calls its trusted cancel action. Neither CopilotKit nor a frontend tool can directly execute a financial mutation. The page may show a finished AG-UI turn while the bank intent remains `PREPARED`.

## Current limits

- CopilotKit/Python conversation memory is process-local. Same-session page refresh restores the transcript for display and the pending bank review through an owned task-state read without rerunning the Agent. If a stream was interrupted, the page performs bounded polling of that owned task state. Recovered transcript messages are deliberately kept out of the live AG-UI client state; reinserting them prevented the next run after cancellation. Process-restart recovery is unavailable.
- The experimental page shows text, tool progress, a bank-computed spending aggregate card, a bank-owned confirmation card with selected bank terms, and the trusted task outcome after confirmation or cancellation. A live card-freeze confirmation resumed the original anomaly-check goal; a separate reminder confirmation persisted one reminder. Dedicated investment and mandate card coverage and richer cross-domain partial-completion presentation remain open.
- Card, transfer, investment, schedule, split, mandate, and reminder confirmation still use the bank boundary. Any unsupported intent kind is shown without a confirm control and can be handled on the legacy page.
- Real DeepSeek/PostgreSQL browser acceptance covers account query, spending visualization, transfer preparation, bank step-up confirmation and exactly one completed transfer, refusal, product comparison, card freeze then anomaly query, reminder creation, a fresh three-domain read, same-process refresh, interrupted-stream recovery, hostile-note spending reads without financial intent, forged client state rejection, concurrent confirmation replay, and two-customer transcript/review isolation. Hostile-note answer quality and long-thread three-domain completeness remain open in the acceptance ledger.

To roll back, set `AGENT_UI_V2_ENABLED=false` and redeploy the web and Agent services. No Customer/Public OpenAPI or financial schema changed.
