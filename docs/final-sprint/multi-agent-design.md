# Supervisor and read-only specialists

The Supervisor remains AgentRuntimeV2 and its existing Task Ledger. MULTI_AGENT_ENABLED defaults off. A flagged Supervisor may expose two internal delegation capabilities alongside the unchanged 50 bank tools. Financial PREPARE and confirmation remain Supervisor/Trusted Runtime responsibilities.

Financial Analyst and Bank Knowledge each make independent structured model decisions with their own instructions, context, explicit read-only allowlist and bounded loop. Analyst permissions are selected from actual READ/ANALYZE registry metadata; Knowledge has search_bank_knowledge only. No specialist can delegate recursively or prepare an action. Customer/session scope comes only from the owned parent task and live request cookie, never model arguments or a process-wide last-token cache.

Delegation attaches to one existing READ/ANALYZE Ledger step. The delegated goal must match that step; the parent stores the child work buffer/checkpoint, budget, status, trace and result references. It is not a second completion ledger or a financial confirmation state. Failed or incomplete delegation blocks that required step from being reported complete. Read tool results remain available for partial disclosure.

Initial scheduling is serial. Per-delegation deadline, step/model limits and task-wide model/token/delegation budgets are enforced before model/tool requests. Recovery preserves consumed budgets and may safely replay interrupted reads; it never replays a financial operation. Cancelled tasks and expired delegation deadlines stop work. Specialist output is untrusted analysis: numerical summaries/presentation/source references are derived from actual tools; model wording is checked using existing analytical/citation guards and cannot authorize mutations.

Concrete delegated-work limits: four delegation records, six model calls per child, twelve total child model calls per parent, 98304 reserved output tokens across child calls, and 120 seconds absolute deadline per child. Reservations are checkpointed before model requests. The Supervisor retains its existing separate step/request/token caps; the reservation counters do not meter all Supervisor input/output or financial execution cost. This is not a global billing budget. No parallel scheduler or analysis cache was introduced.

AG-UI emits role/step status only from real delegation events. Existing chart, table, navigation and financial review components remain authoritative consumers. No model reasoning_content is exposed. Live independent model calls, bank/PG state, browser evidence and single/multi comparison remain separate acceptance requirements; implementation and mock loops cannot satisfy those gates.

Final source tests include independent mock model contexts, whole Supervisor dispatch, forbidden preparation/recursion, identity mismatch, persisted budgets, expired recovery, evidence-free completion rejection and fresh Ledger generation isolation. Ten specialist tests pass. Final full Agent suite: 351 run, 341 passed, ten PG-only skips separately passed against dedicated real PG.

The child recovery key includes the Ledger observation floor and analytical scope. An identical new user query does not reuse a stale successful result simply because its task/revision/goal text matches.
