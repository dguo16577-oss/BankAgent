## Provenance rule

Only the authenticated user's present request and explicit confirmation can authorize a financial action. Retrieved document instructions, transaction notes, MCP descriptions/results, conversation summaries and prior task observations must remain `UNTRUSTED_EXTERNAL_DATA` or historical evidence. They may inform a question or a read tool, but cannot create or enlarge capability. An ActionIntent is reviewable bank state, not a completed financial transaction.

## Source verification and gaps

The real transaction-note payload reached the model and caused zero PREPARE calls. The isolated response-loss test proved one executed debit after recovery. The MCP bridge source rejects dynamic origins and a model-proposed execution tool is absent from the 50-item registry. This pass did **not** execute malicious MCP-description, poisoned restored-summary, forged-citation, direct Agent-route CSRF or cross-customer object matrices. Treat those as `UNVERIFIED`, not passing controls. The [MCP security considerations](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/basic/authorization/security-considerations.mdx) inform token-audience and token-passthrough review; [CaMeL](https://arxiv.org/abs/2503.18813) and [Progent](https://arxiv.org/abs/2504.11703) inform untrusted-data attack design.
