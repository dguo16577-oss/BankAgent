## Financial invariants and state names

The existing task API uses `SUCCEEDED`, `PARTIAL`, `FAILED`, `BLOCKED`, `WAITING_CONFIRMATION` and `WAITING_AUTH`; it does **not** expose a separate `UNKNOWN` task status. Unknown bank execution is represented by `execution_uncertain=true`, `WAITING_AUTH` and error `EXECUTION_OUTCOME_UNKNOWN`. Ledger steps use `SUCCEEDED`, `PENDING`, `FAILED`, `BLOCKED`, `CANCELLED` and `SKIPPED_CONDITION_FALSE` as appropriate. A PREPARE produces an intent, never a confirmed financial receipt. A financial step succeeds only with a trusted `confirmed_*` observation containing a unique bank receipt ID. A cancelled or failed prerequisite blocks dependent preparation. Bank-side authorization, intent hash, idempotency and account balance remain authoritative; the LLM cannot turn tool text into user approval.
