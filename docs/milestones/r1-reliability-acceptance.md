## Financial invariants and limitations

No PREPARE executes by itself. Every tested mutation passes through user confirmation and Spring; two-worker tests show one financial debit; cross-customer task lookup is denied; a cancelled intent cannot be reconfirmed. Prompt-injection defenses remain in the existing registry/analysis tests, but a dedicated R1 real-model injection run was not added. Unknown non-transfer execution outcomes are intentionally `PARTIAL`, not replayed. The lease has no renewal heartbeat. The conditional-ledger false/unknown branch lacks a trusted evaluator. Neither a card freeze nor subscription stop is transactionally reversible as a group.

The isolated real-model cross-domain chain exposed an initial pure-query guard false positive on “冻结1937，然后查询异常交易……”. The guard now permits an explicit action within a mixed request while preserving read-only handling for “为什么我的卡被冻结了？”. Automated regression and a real model run passed that point. A stochastic malformed ledger once returned `MODEL_INVALID_OUTPUT`; bounded ledger parsing retry was added and the subsequent run continued.

### 2026-10-13 AG-UI recovery follow-up

The current worktree Web and Agent images were rebuilt and restarted in the isolated Compose deployment at `http://127.0.0.1:18088`. The AG-UI page returned HTTP 200. A real DeepSeek browser test prepared a 1 CNY transfer to Lin Wei, reloaded the page, and restarted the Agent process. Both times the same bank task remained `WAITING_CONFIRMATION`, its review card reappeared, and the balance was unchanged. No transfer was confirmed.

A second browser test interrupted an active `RUNNING` read-only multi-domain AG-UI stream by taking the browser offline, then restored connectivity and reloaded. The bank task reached `SUCCEEDED` with the same task ID and no balance change. The first run exposed a real recovery defect: the UI was blank because it removed the in-flight marker when the task merely entered `RUNNING`, and its CopilotKit transcript was empty after the SSE disconnect. The fix keeps that marker until a terminal/waiting state or newer transcript is available, and restores the last user turn and final answer from the session-owned PostgreSQL task checkpoint. The Agent masks secrets and long account numbers before returning this recovery text. The repaired real-browser suite passed **2/2** with Agent restart enabled; the disconnect case also passed separately after asserting the interruption happened during `RUNNING`. The Agent adapter tests passed **9/9**; Web **510/510** tests, lint, typecheck and production build passed. This establishes R13 for the isolated AG-UI deployment; it does not close R10–R12 or the unfinished cross-domain chains. Recovery from an empty CopilotKit transcript reconstructs the latest turn and answer, not the full conversation history.

### Fault observed during R12 and repair

The first concurrent confirmation run exposed a separate timeout: the bank committed both actions once, but subsequent DeepSeek calls ended in `MODEL_TIMEOUT` / `BLOCKED_PROVIDER`. Nginx cut `/api/agent/chat` at 30 seconds, before the Agent returned, so the page incorrectly displayed “Bank action failed” and left a stale review. The saved tasks still contained one bank receipt each. A route-specific 180-second proxy read timeout was added to [aster-routes.conf](../../infra/nginx/aster-routes.conf); `nginx -t` and reload passed. A fresh rerun completed both customers' full goals in 28.2 seconds, and the same-intent two-tab test passed in 11.9 seconds. A future model outage can still pause a task after a bank commit; the durable bank receipt and task state must remain the recovery authority.

### Ledger audit

`Task.goal` stores the original request, `Task.ledger` stores subgoals, dependencies, statuses and observation references, `completed_intents`/`completed_actions` store bank action references, and `agent_state.tasks.state_version` persists the compare-and-swap version. In the successful R12 tasks, every ledger step was `SUCCEEDED` and had at least one observation reference; financial steps referenced `confirmed_*` observations rather than prepared intents. The first R12 timeout left complete evidence in PostgreSQL while the task was `BLOCKED_PROVIDER`, correctly avoiding an unsupported final success claim.

There are remaining completeness gaps: `update_ledger()` verifies evidence tool names and bank confirmation observations, but does not deterministically enforce every declared dependency. `failure_reason` exists in ledger rows but is not populated for the rejected R10 bank action; its code is instead stored in `failed_actions` and trace. A semantic model audit follows evidence checking, but the independent real-model audit can itself time out after all bank work is complete. Conditional false/unknown branch evaluation has not been proven end to end. These gaps keep overall R1 at **PARTIAL**.
