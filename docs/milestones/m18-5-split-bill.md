# M18.5 Split Bill / AA — implementation checkpoint

**Status: PARTIAL (2026-10-08).** Flyway V23/V24 persist split bills, participant requests, and immutable create/cancel action intents with step-up authorization binding. Six compatible Customer API operations support owner/participant reads and action prepare/read/revoke/confirm. The bank checks the receiving account, exact CNY minor-unit shares, verified participant routes, unique target customers, and the reviewed intent hash. Participants can read only their own request; creation does not debit them. The [approved proposal](M18-5-SPLIT-BILL-PROPOSAL.md) describes the schema and API.

Agent v2 uses the existing `calculate_split` and recipient resolution tools, then selects `prepare_split_request` or `prepare_cancel_split_request` in the same LLM/tool loop. A revised amount or participant set first revokes the old bank intent. A valid prepared action stops at `WAITING_CONFIRMATION`; only the trusted step-up and confirmation path creates or cancels the persistent request. PostgreSQL tests cover scoped visibility, exact shares, replay, cancellation, no debit, and concurrent confirmation.

Customer contract revision 1.23.1 fixed a real `CANCEL` validation bug: generated Java code initialized an omitted optional participant list to empty, while unconditional `minItems: 1` rejected it before the controller. The server still requires participants for `CREATE`. The failed first lifecycle run is retained in [run history](../../artifacts/m18-smart-actions-run-history/7a10f74dcf294346a9e53178cdfe1dd1/); the [passing real-model create/cancel run](../../artifacts/m18-smart-actions-lifecycle.json) proves model-selected cancellation, trusted confirmation, final `CANCELLED` state, and no debit in PostgreSQL. The [four-case run](../../artifacts/m18-smart-actions-model-smoke.json) also covered AA preparation and a two-turn total revision. **A01–A13 have not been fully graded**, so M18.5 is not yet accepted as PASS.
