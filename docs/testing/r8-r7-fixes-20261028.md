## 已修改

### R7-LIVE-01：同范围消费重复出卡

`presentation.py` 在当前 observation floor 和有界窗口内，以规范化请求期间、非币种筛选
（包括账户、卡、分类、商户及其他 scope 字段）、币种、统计粒度、比较期间组成选择键。
同键选择**最近一次成功工具观察**，整个币种的卡片、图表和表格使用同一份观察，不相加、不按金额去重。
覆盖信息变化也使用新观察；不让旧的完整结果掩盖新的缺失月份或对账错误。

CNY-only 与 all-currency 无论先后，每种币种各出一组；不同账户、卡、月份、粒度和比较期间
仍保留。时间规范化保留亚微秒小数；未知期间不强行合并。原 Observation 和持久任务数据不变，
刷新重建使用同一确定性规则。质量检查仍针对原观察执行，不因按币种选展示而丢掉错误。

### R7-LIVE-02：JSON 失败分类与重试

保留原 Planner 最多两次尝试，不增加无限重试、不解析任意夹带文本、不更改金融参数。
模型的空 content、非字符串、Markdown 围栏、无效 JSON、非对象 JSON 现在得到固定分类。
只将分类和 content 长度写入脱敏诊断并回灌 `schema_repair`；不保存失败正文、隐藏思维链或异常原始 doc。
下一次仍要求一个严格匹配原 schema 的 JSON 对象，原工具、条款和授权校验保持。
持续无效时仍安全终止为模型错误，不能靠猜测创建 Intent。

r7 首次失败没有保存原文，本轮不能追认其语法原因，也不能保证模型以后不会再返回无效 JSON。
修复目标是让有界纠正更具体、失败可诊断，不能把 HTTP 200 当成功率。

### GAP-02：构建指纹

新增 `scripts/build-fingerprint.ps1`。Web 哈希覆盖实际应用树、锁文件、workspace、兼容包、patch、
Dockerfile、构建脚本、docs/audit、dockerignore；Agent 覆盖 app、requirements、Dockerfile 等。
启动器使用 v2 哈希，并在每个构建前同时复核物理和提交余量。
依赖、patch 或 Dockerfile 改动不再被原 src-only 哈希漏掉；缓存/密钥文件不参与。

这是**源码构建输入指纹**，不是镜像 Digest，不证明浮动基础镜像/tag 没变。
实际部署仍必须同时记录 Commit/dirty tree、Image ID/Digest、配置和数据库版本。
旧标签不可与新 v2 标签直接比较。本轮没有新增金融工具、修改合同或迁移。
