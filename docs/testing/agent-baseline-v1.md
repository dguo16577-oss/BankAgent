## 复现

在项目根目录运行：

```powershell
pnpm test:agent:eval
```

分享或人工检查评测集时，运行 `pnpm agent:eval:export`。它从同一份 Python 场景和 fixture 生成 [场景 JSON](../../artifacts/agent-eval/scenarios-v1.json)、[场景 CSV](../../artifacts/agent-eval/scenarios-v1.csv)及[合成数据 JSON](../../artifacts/agent-eval/fixture-v1.json)。CSV 使用 UTF-8 BOM，便于直接用 Excel 打开中文。`prompts` 等多值字段在 CSV 单元格内是 JSON 数组；多轮题的提问顺序不会丢失。`must`、`any_of`、`absent`、`paths` 是评分条件，并非完整标准答案。

也可运行 `python scripts/agent-eval.py`。脚本在进程内调用 FastAPI ASGI；不启动 Spring、PostgreSQL、Web 或 DeepSeek。它为每题重建 Alex/Lin 合成资料、只读银行 API 模拟层和无网络分类器。日期、账户余额、交易、收款人、卡片、公开资料均固定。金额使用十进制字符串和 `Decimal` 检查，Alex 的 `23842.31 - 120.00 = 23722.31` 与 pending 交易对应。转账只允许生成提案，模拟层没有 mutation 接口。

运行器检查答案中的关键事实、禁止内容、引用、提案类型和工具路径；多轮题连续发送同一进程的消息，跨用户题切换会话标识。它不会用 LLM 判断答案正确性。`R03` 检查无效模型意图不能选择任意工具；`R04` 当前仅检查调用有界，**不证明未来工具循环正确**。

## 下一步顺序

1. 修复优先级最高的财务语义与路由：消费/转账混合问题、收款人空格、金额及统计窗口。新增回归用例后重跑基线。
2. 为 Agent 加入受控工具调用循环：模型提出工具调用，服务端校验 schema/权限并执行，再把结果交回模型判断。设置步数、时间和 token 上限；业务事实仍以银行 API 为准。
3. 实现会话隔离的多轮上下文与明确的提案审阅边界，不让模型文本直接执行资金操作。
4. 补 72 条英文/改写表达并人工审核标准答案；冻结留出集，进行在线 DeepSeek 多次运行、延迟/成本统计。
5. 最后在隔离 Spring/PostgreSQL 环境跑双用户与真实会话集成。真实转账须在银行页面明确确认和验证，评测不直接执行。

## 限制

本版 fixture 是**合成数据**，不是当前数据库快照；公开来源内容也为测试样例。安全组 4/4 只覆盖四个固定攻击样本。没有做真实模型工具调用、真实后台服务重启、前端浏览器或跨端口转账验收。这些都不能用本报告的通过数代替。
