# Demo deposit and currency-account APIs

Customer contract revision 1.16.0 adds three session-authenticated endpoints. Mutations require the existing CSRF header. `POST /customer/currency-accounts` opens a zero-balance account in one of USD, JPY, EUR, GBP, HKD, AUD or SGD; it does not exchange or fund money. Each customer can hold one active multi-currency account per currency. The API returns a masked identifier and a zero CNY equivalent using a clearly marked `DEMO_RATE` reference.

`GET /customer/time-deposits` lists owned 12-month deposit holdings. `POST /customer/time-deposits` requires a CNY source account, a positive decimal-string amount, the customer's password confirmation, explicit confirmation and an `Idempotency-Key`. The backend locks the customer and source account, checks the available balance, debits the source, opens a separate `TIME_DEPOSIT` account, creates one debit and one credit transaction, and records the holding in one PostgreSQL transaction. A replay with the same key and request returns the same holding; reuse with different terms fails. No password or full account identifier is persisted in the deposit record.

The annual rate is read from the demo public rate catalog at execution and stored on the holding. It is an illustrative fixed annual percentage, not a real quote or an accrued interest balance. Time-deposit principal cannot fund transfers or investment orders. The current demo has no maturity payout, interest accrual, renewal or early withdrawal workflow. The account's displayed `availableBalance` still follows the shared balance-minus-pending convention; the UI labels this principal as locked and hides the transfer action. FX accounts remain zero-balance until a separately designed, executable FX funding flow exists.
