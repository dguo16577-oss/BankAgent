## Adaptation rule

For every selected row, retain `source_id`, archive hash, original case ID, license, and a transformation log. Create an immutable M18 JSONL manifest with the user turns, explicit tool capability, disposable PostgreSQL seed, exact expected task state, direct DB invariants, and forbidden side effects. Pre-register the manifest hash before a real DeepSeek run. Never reuse a synthetic `sim-*` ID as a bank canonical ID, count the same dialogue under both source and standardized files, or treat `HONEST_NOT_IMPLEMENTED` as success once the bank capability exists. Keep train/dev/locked-test assignment at the `group_id` level after human review.

`ST-S09` is the first candidate when the Smart Transfer acceptance suite needs another independent identity-boundary case. It requires two owner-scoped saved recipients with the same phone number in disposable PostgreSQL and a revised `WAITING_USER` oracle. It has **not** been run or added to the benchmark denominator. The current priority is completing the scheduled-transfer and split-request business flows; the handoff's draft cases remain available for later review without blocking that work.
