# 智能转账样例集 v1（草案）

本文件对应 [20 条 JSONL 样例](smart-transfer-samples-v1.jsonl)。这些是**合成、待人工复核的场景设计**，不是已通过的评测结果，也不计入既有 20 条真实 DeepSeek 试运行集的通过率。所有客户、手机号和交易均为虚构数据。

## 覆盖范围

| 方向           | 样例    | 当前 Agent v2 能力         | 重点验收                                                                                |
| -------------- | ------- | -------------------------- | --------------------------------------------------------------------------------------- |
| 姓名转账       | S01–S06 | 已实现                     | 中文、拼音、英文、同名消歧、金额/收款人修改；确认前零扣款。                             |
| 手机号找收款人 | S07–S09 | 未实现                     | 唯一、无匹配、多匹配；当前只可说明限制或安全澄清。                                      |
| 历史备注找人   | S10–S12 | 完整转账流程未实现         | `note` 已可持久化和检索；仍缺备注→已验证收款人→转账的闭环。备注里的命令只作不可信数据。 |
| 定时转账       | S13–S15 | Agent 流程未实现           | 时间/时区、取消与状态；当前不能把定时请求误做立即转账。                                 |
| AA 拆分收款    | S16–S18 | 未实现                     | 收款请求、分角规则、部分付款状态；只读算术不等于创建收款。                              |
| 安全边界       | S19–S20 | 核心边界已实现，样例待实测 | 余额不足、收款人昵称提示注入；不得产生额外 intent 或扣款。                              |

## 如何使用

每行有 `initial_state`、多轮 `turns`、`oracle` 与 `capability_status`。`split=unassigned`、`review.status=DRAFT` 表示尚未进入锁定评测集。交接人应先将每条状态做成可重置沙箱 fixture，核对现有接口与业务语义，再由两人复核 oracle，最后按 `group_id` 分 train/dev/locked-test。

`NOT_IMPLEMENTED` 的 `oracle.allowed_outcomes` 描述**当前安全行为**；`future_target` 描述将来功能完成后的目标。不得把当前的诚实拒绝计为手机号、历史备注、定时或 AA 功能成功，也不得将这 20 条草案加入现有 80% 通过率分母。

目前真正已运行的 20 条转账测试见 [既有试运行集](aster-transfer-eval-v1.jsonl)与[重复运行报告（历史资料）](../../docs/release-status.md#历史资料)。六大比赛场景的数据处理规范见[交接要求（历史资料）](../../docs/release-status.md#历史资料)。
